The Solution

Structured specs that
act as contracts

VibeLoom generates a tiered stack of specifications. Each tier constrains the next. Upstream specs serve as evaluations for downstream work.

Contract Stack

Intent → PRD → Domain Model → Architecture Spec → Code. Each tier is verified against its upstream contracts.

Domain Model Anchor

DDD-style domain model is the semantic core. It captures user value independently of technical decisions — the most stable layer.

Multi-Agent Ready

Modules derived from bounded contexts. Each fits one context window. Interface contracts prevent incompatible APIs between parallel agents.

Specs as Evals

Three-tier evaluation: structural checks (blocking), semantic coverage analysis (warnings), and test generation from specs (on-demand).

Bidirectional Consistency

Edit any spec — upstream and downstream are checked automatically. Bounded reconciliation: one up-pass, one down-pass, no infinite loops.

Human Governed

Every tier requires human approval. Agents generate, you verify. Force-approve with documented issues when pragmatism demands it.

One command to rule them all

Type /vibeloom with no arguments and the Agent figures out what to do based on your project state.

/vibeloom generate Generate next artifact
/vibeloom approve Approve after review

/vibeloom reconcile Fix after manual edits
