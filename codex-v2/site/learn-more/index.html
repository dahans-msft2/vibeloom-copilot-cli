VibeLoom is a methodology for AI-built codebases that need to remain coherent after the first sprint.

The problem is not that agents cannot generate code. The problem is that prompt-first systems struggle to preserve workflow truth, domain meaning, and interface ownership as the codebase evolves. VibeLoom introduces a compact set of contracts that keep those layers explicit without turning the process into prose theater.

Core principles

Intent-first

The methodology starts from what the system is for, then climbs toward technical realization instead of beginning with architecture or pseudocode.

USM and DM are both mandatory

User workflows and domain semantics are separate layers. VibeLoom refuses to collapse them into one blurry artifact.

Derived guidance stays derived

Agent instructions and change plans are execution aids, not semantic authorities.

Projection restraint

The system allows only a trace index, stale graph, and interface manifests as durable projections so the method does not create its own context burden.

The contract stack

Intent PRD USM DM Spec Derived AGENTS / Plan Code + Tests

Why USM matters

USM is the easiest semantic layer for humans to validate. It reveals user value, story order, and workflow assumptions before the project hardens into technical structure.

Why DM matters

DM protects ubiquitous language, invariants, and concept ownership. It is the layer most likely to survive architectural churn without losing the meaning of the system.

Workflow

1. Greenfield initialization

Draft intent, then reconcile PRD, USM, and DM before technical decomposition begins.

2. Technical design

Translate approved semantics into module boundaries, interface ownership, and execution policies.

3. Derived execution

Generate scoped agent guidance and a change plan from the approved truth instead of improvising from a giant prompt.

4. Reconcile change

When manual edits or code drift appear, propose whether upstream semantics or downstream implementation should move.

Import is bootstrap, not routine defect handling.

Brownfield repos can be brought under governance through import. Once governed, defects should be resolved locally from a repro, expected behavior, and regression coverage.

Profiles and change classes

Concept Definition
Lite Lower coordination risk, but still requires both USM and DM.
Full Multiple bounded contexts, explicit modules, interface ownership, and dependency rules.
Local Small implementation or content change with no semantic or interface impact.
Behavioral-in-module Behavior changes inside one semantic or technical boundary.
Boundary-changing Actors, workflows, concepts, interfaces, or NFRs change across boundaries.

Where VibeLoom differs from adjacent approaches

Tighter than prompt-only

It is willing to introduce explicit contracts because long-lived systems need stronger semantic memory than a chat transcript can provide.

Heavier than lightweight feature specs

That weight is intentional. VibeLoom is for larger and longer-lived codebases, not for squeezing the most speed out of every tiny edit.

Lighter than process theater

It keeps the artifacts concise, structured, and machine-checkable. It refuses an unlimited pile of projections and generated paperwork.

Need the short version?

VibeLoom helps agents move fast without letting the codebase forget what it means.
