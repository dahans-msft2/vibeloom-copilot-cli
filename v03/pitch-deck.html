03 / 11 Why prompts don't scale

Chat history isn't memory. The next agent starts cold.

Prompts are a tactical fix for a structural problem. The structural fix has to live somewhere more durable than the chat window.

A · Prompts decay

Better prompts solve one run, not the next.

Steering files, sharper instructions, stricter rules — works for one session. Dies on the next agent, the next contributor, the next branch.

B · Comprehension debt compounds

17% lower comprehension on AI-assisted work.

Anthropic's research, surfaced via O'Reilly. Largest drop in debugging — exactly where you need to understand the system. The reckoning arrives quietly.

C · The codebase is the only artifact

And by 2026, it's too large to internalize.

Every cycle starts cold. The codebase is the only durable artifact — and it's already past any single human or agent's working-memory ceiling.

"Making code cheap to generate doesn't make understanding cheap to skip. The comprehension work is the job." — Addy Osmani, O'Reilly Radar · Apr 2026

08 / 11 The moat

A deterministic engine. Not a prompt template.

Anyone can write a clever prompt. Almost no one is building the deterministic substrate that makes contract-driven generation auditable, reproducible, and learning-loop-ready.

01 · Engine

Deterministic Python, zero runtime deps.

Parse, validate, build the contract graph, compute affected sets, plan dispatch, detect drift — all without an LLM call. Auditable, reproducible, fast.

02 · Traces

Six trace families, append-only JSONL.

approval · generation · eval · code-sync · decision · import. Every run leaves provenance. Substrate for a future learning loop and for graph promotion.

03 · Verification ladder

Decidable → mechanical → heuristic.

Honest answer to "what does semi-formal verification mean in 2026?" Trajectory is to promote heuristic checks to mechanical, mechanical to decidable, as the engine matures.

04 · Parallel dispatch

Wave assembly + scoped subagents.

Multi-component regeneration in parallel, with bounded load sets and validation contracts per task. Code-sync traces close the loop back to contract IDs.

Defensible because it's an operating model, not just code. The methodology, the trace schemas, and the ladder compound over time. A wrapper around an LLM doesn't.
