codæ

Contract-driven agentic engineering.

Agentic AI coding crashed the cost of producing code. It didn't crash the cost of holding a system together. As autonomous agents extend codebases past any single human's comprehension, semantic drift accumulates and "AI slop" compounds — measurable, in 2026, in real codebases. This whitepaper argues for governing it through a stack of human-mendable contracts: smaller than the code, persistent across agents, verifiable against what ships.

§1 — The destinationCoding goes dark factory.

A "dark factory" runs lights-out — no humans on the floor, just machines. The product flows in as a specification and out as physical units. Workers exist; they design the line, audit outputs, evolve the spec. They do not turn the wrenches.

The same pattern is forming in software. The highest-leverage end-state of agentic coding is the dark factory: agents write the code, run the tests, fix the failures, open the pull requests, and merge them. Humans set direction, govern the contract that steers the factory, and audit what flows out. The factory floor is dark.

The pattern is no longer aspirational. In February 2026, Spotify confirmed its best engineers had not written a line of code since December — they were merging hundreds of agent-authored PRs per month through Spotify's internal coding-agent platform.2 BCG Platinion's Dark Software Factory report named the milestone explicitly: "as few as three engineers can run a software factory where humans no longer write code."3 Sequoia, in their January 2026 essay declaring the practical AGI year, named the underlying capability shift: coding agents that plan, use tools, maintain state, and loop until success.1

The economics: the industry-promised 10–100× speedup from agentic coding lives in exactly one place — the dark factory. The moment the human has to drop into the code to fix what the agent built, the speedup collapses. codæ commits to dark-factory coding as the multi-year trajectory, not as a v0.3 promise.

§2 — The blockerCoherence fails, and the factory cannot stay dark.

The capability threshold has been crossed. The gating constraint is coherence: preserving intent, architecture, domain meaning, and behavior across long-running, multi-agent work. When coherence fails, the symptoms have names:

  • Semantic drift — outputs progressively diverge from original task intent while remaining syntactically valid.
  • AI slop — cheap to generate, expensive to review.
  • Comprehension debt — the codebase looks clean, but no human (and no incoming agent) understands what it's doing or why.

Local fixes — better prompts, sharper instructions, stricter reviews — don't get past this. They work for one run and die on the next agent. The bottleneck isn't model capability; it's the absence of a durable, inspectable control surface above the code. With one in place, drift stops being a vague quality problem and becomes a concrete contract violation: detectable, attributable, localizable, and repairable at the contract boundary, before humans are pulled back onto the floor.

§3 — The contractThe control surface that holds the factory together.

A prompt cannot govern a dark factory. A codebase is too large to be the human control surface. A requirements document is too weak if agents can ignore it. The missing object is a contract — a set of mutually-derived specs tied together by a graph: authoritative enough to govern generation, structured enough for agents to consume, small enough for humans to mend.

The load-bearing question is what surface humans can hold. Not lines or tokens, but the number of meaningful items in the affected review cut — code-level (files, classes, methods, branches, tests, integrations) versus contract-level (capabilities, constraints, requirements, flows, bounded contexts, interfaces, behaviors, decisions, obligations). A contract is a different shape: a small set of concepts at the right abstraction level governing a much larger set of implementation paths.

Cognitive surface, to scale. A 108K-line system (left) lies far above any human comprehension ceiling. The contract governing it (right) — intent, requirements, structure, behavior, config — is roughly 24% of the code volume and fits below the ceiling. Humans hold the right side. Agents extend the left. The contract is the bridge.7

For the contract to be load-bearing, it has to do four jobs at once:

  • Edited by humans — so it must be smaller than the code.
  • Kept consistent with AI's help — so it must be machine-checkable.
  • The long-term memory the next agent inherits — durable across sessions, independent of chat.
  • The eval signal every generated artifact is verified against — drift becomes detectable, not hopeful.

A graph-tied set of mutually-derived specs satisfies all four. That is the contract. That is the bridge to dark factory.

§4 — The betGenerated implementation is not the source of truth.

The choice underneath codæ is binary. One option: keep code human-mendable. The agent drafts; the human reviews, edits, ships. Useful — but not a dark factory. The other option, the bet codæ makes: code is generated, regenerated, treated as downstream infrastructure. The contract is what humans maintain. The contract is what agents satisfy. The contract is what detects drift. The contract is what receives repair.

From spec-driven to contract-driven

Spec-driven development8 — across AWS Kiro, GitHub Spec Kit, BMAD — places existing approaches across rigor levels: spec-first (specs guide, then drift), spec-anchored (specs and code co-evolve with enforcement), spec-as-source (specs alone are edited; code is regenerated). All three are real progress over prompt-only generation. codæ is the next level: contract-driven — not one spec for one file or one feature, but a multi-tier, mutually-derived, graph-tied, drift-detecting contract that governs the whole lifecycle. Same impulse, larger surface, longer arc.

The compiler was software's first dark factory.

Software has done this climb before — one abstraction level down. We used to inspect generated machine code; now we inspect source, trust the toolchain, debug through traces. The compiler is the canonical dark factory: humans write source, the toolchain compiles, nobody reads the assembly. We trust it because its contract is decidable. codæ proposes the same move one level up: humans inspect the contract; agents compile it into implementation. The analogy is not a proof — a compiler is deterministic, agentic generation is not — but it clarifies the desired control surface.

The goal is not less slop. The goal is a factory that stays dark.

— codæ thesis

Govern agentic code generation by a contract — so humans can leave the factory floor. Contract in. Production system out. Humans mend. Agents compile. We call the discipline codæ.
