codæ

Contract-driven agentic engineering.

Agentic AI coding has dramatically lowered the cost of producing code. It hasn't lowered the cost of holding a system together. As autonomous agents extend codebases beyond what any single human can comprehend, semantic drift accumulates and "AI slop" compounds — measurable, in 2026, in real codebases. This whitepaper makes the case for governing it through a stack of human-mendable contracts: smaller than the code, persistent across agents, and verifiable against what gets built.

§1 — The slop problemGeneration got cheap. Coherence didn't.

Agentic coding broke the bound that used to keep drift human-paced. A multi-turn agent now extends its own prior code, summarizes its own context, and re-derives its understanding every turn — at machine speed, without any single human holding the mental model. Every cycle is a chance for meaning to slip. The slips compound.

The same failure shows up under different names in the 2026 literature:

  • Semantic drift — outputs progressively diverge from original task intent while remaining syntactically valid.
  • AI slop1 — code that looks reasonable, passes review-by-glance, and accumulates faster than reviewers can absorb. Cheap to generate, expensive to review.
  • Comprehension debt2 — the codebase looks clean, but no human (and no incoming agent) on the team understands what it's doing or why.

One structural problem under three names: agentic systems now produce code faster than humans can integrate it into a coherent whole. Drift is no longer an aberration. It's the equilibrium.

The pattern across all of these: agentic generation works as a bounded operation but degrades when bound to long-running, multi-component, multi-agent systems where coherence has to be preserved. The bottleneck is not model capability — it's the absence of a durable, inspectable, traceable control surface above the code.

"AI amplifies the quality of the engineering system it operates within."

— DORA 2025 report on AI-assisted development6

§3 — Cognitive surfaceCount items, not lines.

The right way to compare what a human can hold in their head is not lines or tokens — it is the number of meaningful items in the affected review cut. At the contract level: capabilities, constraints, requirements, flows, stories, bounded contexts, components, interfaces, behaviors, decisions. At the code level: files, classes, methods, endpoints, branches, tests.

A specification is a different shape. It captures what the system is, not how every line implements it. A small set of concepts at the right level of abstraction can cover a large set of code paths. The spec stack is, by construction, a smaller item surface than the code it governs.

Cognitive surface, to scale. A 108K-line system (left) lies far above any human comprehension ceiling. The spec stack governing it (right) — intent, requirements, structure, behavior, config — is roughly 24% of the code volume and fits below the ceiling. Humans hold the right side. Agents extend the left. The contract is the bridge.8

Cognitive-load-aware research9 confirms the principle from a different angle: across 974 MBPP programs, 5,000 APPS programs, and a human study of 20 programmers, structures aligned to working-memory limits reduce failures by 54-71% versus unconstrained prompting and improve comprehension scores by 17-31%. Structure that fits the cognitive surface is an empirical performance lever, not a stylistic preference.

§4 — The betCode goes dark factory. Intent stays mendable.

Code is going dark factory — generated, regenerated, never maintained by hand. The human's mendable surface moves up to the contract.

Spec-driven moved upstream — but per-feature only. Specs drive one cycle, then decay.

Contract-driven governs the lifecycle. A whole-system, derivation-tracked, drift-detecting contract — approved upstream, verified downstream, reconciled when things slip. The dark-factory enabler.

For this bet to work, the contract has to do these jobs at once: be edited by humans (so it must be smaller than the code), kept consistent with AI's help (machine-checkable), serve as the long-term memory the next agent inherits (durable across sessions), and provide the eval signal every generated artifact is verified against (drift becomes detectable, not hopeful).

§5 — The codæ thesisContract-driven agentic engineering.

Govern agentic code generation by a stack of complementary, human-mendable contracts. The stack is smaller than the code, persists across agents, is verifiable against the code, and is approved by humans. We call the discipline codæ.

From spec-driven to contract-driven

Spec-driven development15 — across AWS Kiro, GitHub Spec Kit, BMAD — places existing approaches across rigor levels: spec-first (specs guide, then drift), spec-anchored (specs and code co-evolve with enforcement), spec-as-source (specs alone are edited; code is regenerated). All three are real progress over prompt-only generation. codæ is the next level: contract-driven — the spec stack is not one source for one file or one feature, but the multi-tier, mutually-derived, drift-detecting contract that governs the lifecycle. Same impulse, larger surface.

The compiler was software's first dark factory

We used to inspect generated machine code. Now we inspect source, trust the toolchain, test the result, and debug through traces. codæ proposes a similar move one abstraction level up: humans inspect the contract; agents compile it into implementation. The artifact parser is the frontend, the contract graph is the intermediate representation, traces are source maps, and generated code targets a platform contract such as AWS, GCP, Cloudflare, or a local runtime. This is an analogy, not a proof — a Rust compiler is deterministic, agentic generation is not — but it clarifies the desired control surface.
